Governed systems begin by separating proposals from authority. A probabilistic model can recognize patterns, summarize documentation, and draft useful language, but those strengths do not make it a reliable owner of persistent workflow state. The operating thesis of this repository is therefore probabilistic intelligence embedded inside deterministic systems. Human or model-assisted interpretation proposes; application logic validates and transitions.

Google Cloud's Agent Registry documentation provides a bounded signal for this design discussion. It describes a centralized catalog for agents, MCP servers, endpoints, and standalone skills. Standalone skills are top-level Skill resources rather than inline A2A skill metadata. The documentation describes SkillRevision resources as immutable versioned snapshots, notes that skills can have multiple revisions, identifies Publisher resources, and explains that administrators can govern skill access and lifecycle. These statements are documented facts from the four primary sources listed with this packet.

A reasonable inference is that durable resource identity and revision history make capabilities easier to find, reuse, control, and audit than instructions that exist only inside an ephemeral conversation. That inference is not a claim about Google's internal implementation beyond its documentation. It is an architectural reading of what resource registration makes possible.

The direct structural similarity to Governed Signal-to-Content is deliberately narrow. Both approaches value durable operational identity, controlled reuse, revision history, lifecycle governance, and capabilities treated as managed resources. Google Cloud Agent Registry and Clarity Systems Group are not equivalent architectures, products, or scopes. The comparison concerns principles, not implementation parity.

This repository applies those principles to a different chain of custody. An external signal first receives source identity. Evidence bytes can be preserved locally and hashed, or a URL-only reference can be honestly recorded as not archived. The signal becomes a normalized candidate, passes deterministic duplicate checks, and receives a structured classification proposal that separates facts, inferences, direct similarities, and broader trends. A positive classification does not change state by itself. Application logic verifies the decision and the candidate's prior state before it permits qualification.

The next layer is packet construction. A fixed generator validates human-authored or externally generated drafts, atomically writes five named artifacts and their supporting source and packet records, hashes the outputs, and records warnings for target-length variance. The generator does not publish. It moves the packet only to AWAITING_APPROVAL. A named human actor must approve the exact packet manifest before local release authorization becomes available.

Persistent state makes these boundaries durable. SQLite records candidates, evidence metadata, packet manifests, and approval decisions in a user-selected workspace outside the repository. JSONL receipts append every accepted or rejected transition attempt. Canonical JSON hashing makes structured manifests stable. Evidence replacement is prevented by exclusive file creation and hash verification. A receipt is never updated in place.

The command layer is another governed operating surface. CLI commands map to explicit state transitions. DISCOVERED cannot jump to APPROVED. QUALIFIED cannot jump to RELEASED. RELEASED means locally authorized for downstream publication, not posted to a network. Discovery and interpretation adapters are interfaces only; their future implementations can propose inputs but cannot acquire state-transition authority.

The repository also extends the comparison into areas outside Agent Registry's documented skill-governance boundary: source identity, evidence lineage, approval authority, persistent local workflow state, publication authorization, multi-brand control surfaces, and command receipts. These are this project's concerns, not claims about missing or present Google capabilities.

The broader industry trend is a shift from transient prompt handling toward governable capability infrastructure. As reusable skills, agents, and tools become organizational resources, identity, provenance, revision, access, and approval become design requirements. This trend statement is intentionally broader than the documented facts and is labeled accordingly.

The useful pattern is layered responsibility. Probabilistic systems help interpret the world. Deterministic systems decide what may happen to durable state. Humans retain authority at consequential boundaries. Evidence and receipts make the path inspectable. That combination does not remove uncertainty; it contains uncertainty inside a workflow whose consequential actions can be reviewed, reproduced, and governed.
