# v0.2.0 — Operational Watch Loop

## Milestone thesis

```text
Configured sources
→ candidate discovery
→ evidence record
→ duplicate and revision detection
→ structured interpretation adapter
→ five-artifact packet
→ approval queue
→ run receipt
```

The scope is derived from the [first operational case](../case-studies/google-agent-registry-v0.1.0/README.md) and its [friction log](../case-studies/google-agent-registry-v0.1.0/friction-log.md). It is the smallest set intended to reduce manual structural work across the next three signals while preserving deterministic authority.

## In scope

1. **`gs2c watch` orchestration command.** Resolve one configured local workspace, run readiness checks, coordinate configured source adapters, and stop at governed boundaries. It does not approve or publish.
2. **Official-documentation source-set adapter.** Accept configured public documentation URLs and record per-source resolution, preservation status, content identity when bytes are captured, and honest reference-only status otherwise.
3. **Provider-neutral interpretation proposal interface.** Produce schema-shaped classification and content-input proposals while leaving validation and authoritative transitions in application logic.
4. **Structured run summary.** Return candidate ID, packet ID, all transition run IDs, states, warnings, and manifest hashes so an operator does not reconstruct one run from several outputs.
5. **Sanitized packet and receipt export profile.** Export public case material without local paths or execution usernames, label derivatives, and retain hashes that point back to unmodified canonical receipts.
6. **Post-publication URL recording.** Append evidence of a manually published URL and actor without changing the approved packet or implying that the CLI performed the posting.

RSS/Atom and GitHub Releases discovery adapters are deferred until a real case demonstrates that the official-documentation adapter is insufficient. Scheduled execution is also deferred; scheduler friction was not observed in this case.

## Explicitly out of scope

v0.2.0 will not include:

- automatic social publication;
- autonomous approval;
- a hosted SaaS service;
- a web dashboard;
- multi-user authentication;
- broad multi-domain monitoring;
- bundled local language models;
- scraping behind authentication;
- multi-brand orchestration inside the core engine.

## Validation target

Before releasing v0.2.0, three real developments must pass through the system. A development counts only when it produces:

- preserved evidence or an honest non-preserved reference;
- structured fact/inference/similarity/trend classification;
- all five packet artifacts;
- an approval decision;
- append-only receipts;
- one externally published output with captured evidence.

The Google Agent Registry case is the first operational case, but its external publication URL remains to be captured. Two additional qualifying signals are required.

## KPIs

- qualified signals processed: **3**
- duplicate signals republished: **0**
- packets with all required artifacts: **100%**
- unauthorized releases: **0**
- state transitions with receipts: **100%**
- unsupported documented-fact claims: **0**
- invalid state transitions accepted: **0**
- manual minutes per completed signal: **measured**
- manual data-transfer steps per signal: **measured**
- publication URLs captured after posting: **100% where publication occurs**

## Release gate

v0.2.0 may be tagged only after:

- the bounded features are implemented;
- tests pass;
- three real signals are processed;
- the case studies are reviewed;
- no publication authority has been delegated to probabilistic components.

No v0.2.0 tag or Release is authorized by this roadmap document.

Transition Authority Hardening Slices 1 through 6 are a governance foundation beneath this
roadmap, not an expansion of it. They add exact approval/release artifact binding,
atomic SQLite transition events, recoverable JSONL projection, and Ed25519-authenticated
exact operations plus mediated canonical execution for approval, rejection, and release,
then add a locally tamper-evident canonical event/receipt chain, default-deny capability
policy, and exact brand/channel/destination authorization. Privileged external-effect
and publication adapters remain deferred.
